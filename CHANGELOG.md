# Changelog

## 0.2.0 — 2026-09-06

- Adds two copy controls: each package row copies `name@version`, and the header copies a short environment report — harness version and its provenance, Node and platform, the UTC collection time, every third-party plugin with its version and planes, the harness packages folded to one line when they all match, the builtin count, and any collection warning.
- The report is share-safe by construction rather than by a toggle. The read route is fenced to same-origin loopback because the snapshot names host paths and config keys, and a copy control inverts that fence, so the report carries no filesystem path, no `DSH_HOME`, no user-authored preset name, and no config value. Only a duplicate group names locations, and there the longest common directory prefix is dropped so that only the differing segments — never the shared root that names the host's user — survive.
- The report is always the whole inventory, never the filtered view: the search box and the plane selector shape one reader's screen, and inheriting them would under-report an install silently.
- Every hedge the panel shows survives the copy: an inferred harness version stays marked as inferred, a package with no manifest version reads `name@unknown`, and the collection warnings are carried whole.
- Plain text, one fact to a `- ` line — legible unrendered in a chat window or a file, and line breaks intact where something renders it as Markdown. Punctuation and every label go through the dictionaries, so the Chinese report reads with Chinese punctuation.
- Writes through the harness's own `writeClipboard` from `@deepseek-ai/dsh-client-ui-primitives` (a platform seed, so the bundle requires it rather than inlining it): the async Clipboard API where the page has it, `execCommand` in an insecure context, and silence rather than a false success when the host refuses.

- Registers the reading as a model-facing tool, `dsh_version_inventory`, so an agent in a dsh session can answer a version question itself instead of asking its user to open a settings tab and paste a report back. One optional `package` parameter takes a case-insensitive name substring, which is the difference between twenty-five lines and five for the common question.
- The tool's result is the same share-safe projection the copy control produces. A tool result enters the transcript, goes to the model provider on every following turn, and may be exported later — the same exposure as a pasted report — so sharing one projection keeps the model reader from quietly becoming wider than the human one. It also drops each package's `description`, which is text a third-party package author wrote and which this is the one path that feeds to a model.
- The canonical value is structured and the prose lives in the renderer, per the tool authoring contract: a PTC caller reads fields instead of parsing sentences, and warnings stay structured facts there too. The rendered text is English — the host has no locale service, and `en` is the dictionary's key source of truth rather than a guess at the reader.
- `tools` is a nested injection like `webServer`, so the package now contributes on any profile: headless and ACP get the tool and no panel, a deployment that composes no agents gets the panel and no tool, and neither holds the composition pending. `@deepseek-ai/dsh-tools` stays a `devDependency` — `ToolDefinition` is a type and `register` takes a plain object, so the package keeps its zero runtime harness imports at the cost of validating its own one optional argument.
- Moves the dictionaries and the report builder out of `src/client/` (`src/locales.ts`, `src/report.ts`), since all three readers now share them.

- The read route answers failures as structured facts too (`{ error: { kind: 'forbidden' | 'method' | 'collect' } }`), not as sentences. It previously refused in Chinese and rejected a wrong method in English, both of which reached the panel verbatim: an English reader saw `Could not read the version inventory: 版本清单只对同源的本地连接开放。` This was the one place the package broke the rule it states for warnings — the host cannot know the reader's language — and the panel now writes these sentences from its own dictionary like every other one. An `error` whose `kind` a bundle does not recognize degrades to its raw text, so a newer host stays legible to an older panel.

## 0.1.0 — 2026-09-06

- Adds a read-only **Versions** tab to the dsh web Settings → Plugins section, beside the shipped plugin list: the running harness version with its provenance, Node and platform, `DSH_HOME`, the install root, and the version of every package the harness mounted.
- Reads both harness planes. The profile's own Loader tree comes from `ctx.loader.entries()`; every agent preset's composition comes from the optional `ctx.get('agentPresets').compositionInventory()`, which reads composition files, so a plugin that exists only inside a preset — `@deepseek-ai/dsh-tool-cordis` in the shipped `cordis` preset — is listed even when no session has mounted that preset. Each mount is tagged with its plane and the list filters by plane.
- Resolves each mount's specifier through the Loader's own resolver and reads the nearest `package.json`, bypassing the `exports` map so a package that does not publish `./package.json` still answers. Subpath specifiers fold onto their owning package. A path-like specifier is verified with `existsSync` first, so a missing relative path cannot walk up into an unrelated manifest.
- Groups packages by **directory**, not by name, so two copies of one package at two versions stay two rows. Duplicates are tagged, sorted adjacent, and named in a warning: Cordis matches services, branded types, and `instanceof` on runtime identity, so duplicate copies mismatch silently.
- Shows each mount's config summary, the only thing that tells two mounts of one package apart. Top-level fields only, nested values collapsed to their shape, strings truncated, and any key naming a credential withheld.
- Flags a harness package whose version differs from the running harness version. The dsh family releases in lockstep, so a difference means the install was mixed.
- Serves the snapshot from `GET /dsh-version-inventory/api/list`, fenced to same-origin loopback requests carrying `X-DSH-Version-Inventory: 1`, because the inventory names host filesystem paths.
- Localizes the whole tab through the client locale service, shipping `en` and `zh` dictionaries. Warnings cross the wire as structured facts rather than sentences, because the host cannot know the reader's language.
- Builds against npm DSH `0.1.2-rc.1`; the interfaces it uses were read from local source `0.1.3-alpha.1`. No source build of the harness is required.
